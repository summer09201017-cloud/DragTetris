使用者從 0915 列的「極高 CP」清單挑了三項,一次做完並上線。

■① 🧩 每日殘局(src/puzzles.ts / src/puzzleSolver.ts / src/puzzles.test.ts)

  每天三題(暖身 / 標準 / 挑戰),日期種子 ⇒ 全世界同一組。入口在設定面板。
  型別 = daily-puzzle-kit 的 **D 型(生成 + 機器驗)**:
    生成:把盤面底下那幾列用俄羅斯方塊**完整鋪滿**(exact cover),再挖掉 3~5 塊當題目
         ⇒ 盤面天生有解(把挖掉的放回去就是答案)。
    驗證:**用遊戲本身的 reduce 實跑一遍**才算數。驗不過就換種子(最多 24 次),
         全部失敗就誠實顯示出不了題 —— **絕不發一題沒驗過的**。

  ★ 為什麼這一款做得出別人做不出的題:招牌是「從托盤直接把方塊拖到盤上任一格」,
    所以「掛在突出物下面 / 塞進凹角」這種在一般俄羅斯方塊裡永遠到不了的洞,這裡可解。
    殘局固定跑 support(塞縫)規則,正是為了用上這個能力。

  引擎只加了兩件事,一般對局完全不受影響:
    · `GameState.puzzle` —— true 時佇列**有限**(放完就沒了,不從袋子補牌)
    · `createPuzzleState()` —— `current: null` ⇒ 沒有會自己往下掉的方塊
      (`tickGravity` 開頭就 `if (!state.current) return`,不必另做一條時間軸)

  ⚠⚠ **這一輪最貴的兩個 bug,都是測試咬出來的,而且兩個都「看起來很合理」**:
   ㈠ **求解器把可放區算錯 ⇒ 好題被判成無解**
      我原本用「盤面上最上面那一列**有磚**的列」當可放區的頂。但題目最上面那一列
      有可能整列都是洞(被挖掉的塊剛好在最上層)⇒ 算出來的頂往下掉一列,
      把一整排合法落點排除在外,求解器就說「無解」。7 欄的挑戰題整組被誤判成生不出來。
      **修法**:可放區的頂 = 盤面最底下那 R 列(R 隨消行變少,由呼叫端一路帶下來),
      **不是**「最上面有磚的那一列」。
   ㈡ **7 欄根本鋪不滿 ⇒ 整組出不了題**
      rows×cols 要能被四格的方塊鋪滿,`rows*cols` 必須是 4 的倍數。
      8 欄與 12 欄任何列數都可以,但 7 欄必須是 4 的倍數列(2×7=14、3×7=21 都不是)。
      **修法**:`rowsFor(width, baseRows)` 從指定列數往上找第一個可行的(7 欄會變成 4 列)。

  ⚡ 還有一個不是 bug、但會讓人放棄跑測試的東西:12 欄 ×3 列的鋪滿實測要 **5.4 秒**
    (而且隨種子飄,可能 1ms 也可能更久)。加了一條剪枝「剩下的空白區塊,每一塊的格數
    都必須是 4 的倍數」之後,全部穩定在毫秒級(9 組 build+solve 都 ≤20ms)。
    ★ **測試貴到讓人跳過,比覆蓋率低更危險** —— 這條剪枝是必要的,不是可有可無的最佳化。

  進度存 `tetris.puzzles.v1`,只留 60 天;題目 id 是**內容雜湊**不是流水號
  (重生題庫或補題都不會弄亂玩家的「已解」)。

■② ↩ 悔一步(一局 3 次,src/store.ts)

  存一份 GameState 快照就等於存了整個世界(盤面、佇列、分數、亂數指標全在裡面),
  因為 `reduce` 是純函式、GameState 不帶任何外部參考 ⇒ 還原不會出現
  「分數回去了但亂數沒回去」這種半套狀態。
  只在「方塊真的落定」(events 有 `lock`)時推進悔棋堆 —— 移動與旋轉沒有不可逆的後果,
  存了只會讓三次悔棋被雞毛蒜皮的操作吃光。快照堆刻意放在 store 外面,不進 React 的
  re-render 路徑。

  ★ **用過悔一步的那一局不進紀錄**(但仍然打完賽點)——理由同 creative 沙盒不計分:
    規則不一樣,混在一起比沒有意義。結算畫面會明講。
  ★ **遊戲結束後不給悔**:那一刻已經寫進紀錄也送出了完賽打點,復活會讓「已玩局數」
    與「最高分」兩邊都對不上。而且俄羅斯方塊的結束是幾十步累積的,不是最後一步失手 ——
    悔一步真正救得到的場合本來就在對局中。

■④ 📱 0916 手機體檢(mobile-fullscreen-audit 子代理,iPhone 直向＋橫向實測)

  🔴 **設定面板關不掉** —— 面板總高 903px 對上 844px 的直向畫面、676px 對上 390px 的
     橫向畫面,唯一的「關閉」鈕在螢幕外(橫向要再滑將近兩個畫面高),小孩點進設定就出不來。
     修:`.settings` 改 `position: fixed` + 可捲、卡片 `max-height: calc(100dvh - 20px)`、
     頂端一條 **sticky 的 ✕**、外加 Esc 關閉。
  🟠 側邊控制鈕(暫停/悔一步/設定/滑鼠拖曳/重啟)實測只有 **30px** 高,而同一份 CSS 的
     `.header-btn` 早就寫了「40px 是觸控目標下限」⇒ 那是漏掉不是刻意,補到 44px。
  🟠 HOLD / NEXT 的拖曳抓取區 42px → 44px。

  ⚠⚠ **有一項建議我實測後決定不採用,理由寫在 global.css 該段上方,不要再改回去**:
     子代理建議把桌機版面的門檻從 `min-width: 900px` 降到 600px(理由是「橫放時棋盤只有
     75px 寬,浪費八成螢幕」)。實測:
      ① 棋盤在橫向是**受高度**限制,不是被側欄擠的 —— 844×390 量到的 74×186 已經用滿
         可用高度(1fr 就是 186px),而 8×20 的盤寬高比是 0.4 ⇒ 就算整個畫面高度都給它
         也只能到 156px 寬。降門檻對棋盤寬度**幾乎沒有幫助**。
      ② 那一段最後一行會 `.touch-pad { display: none }` —— 那是手機唯一的
         ⟲ / HOLD / ⤓ / ⟳ / ▼ 備援按鈕。降到 600px 等於讓「手機橫放」的人整排鈕消失。
     ⇒ 為了一個沒效果的改動換來一個真的退步。真要在橫向給棋盤更多空間,得動的是
       「橫向時把標題列與 HUD 收起來」,那是版面重做,不是改一個數字。
     ⇒ 驗收腳本已加一條迴歸項「手機橫放時觸控備援鈕還在」,再改就會紅。

  🩹 這一輪也修掉驗收腳本自己的兩個毛病:
   ㈠ **版號寫死 'v3'** ⇒ 改成從 `index.html` 的 `APP_VERSIONS[0]` 讀。
      那正是 v2 在產品裡修掉的「版號寫死改版必漂移」,只是搬到測試裡而已 ——
      不改的話,每次改版都變成「改功能順便要改測試」。
   ㈡ **「點一下托盤方塊,畫面真的變了」是假紅**:自由模式的種子是時間戳,NEXT 第一顆
      是隨機的,抽到 **O** 的時候轉 90° 的畫面**本來就一模一樣**(O 的四個朝向相同)
      ⇒ 每七次無緣無故紅一次,而產品完全沒壞。改成先用 `?seed=` 挑一顆不是 O 的題號。
      ★ 通則:**畫面比對型的斷言,遇到對稱物件會假紅** —— 要先確保受測對象真的會變。

■⑥ 怎麼跑

  npm install
  npm run dev            # 開發 http://localhost:5173
  npm test               # 110 項
  npx tsc -b
  npm run build
  npm run preview        # 另一個視窗,預設 4173(被占用會自己換 port,**看它印的那個**)
  node scripts/verify-browser.mjs                                    # 打本機
  BASE=https://dragtetris.pages.dev node scripts/verify-browser.mjs  # 打線上
  SHOT_DIR=shots node scripts/verify-browser.mjs                     # 順便存截圖

  ⚠ `npm run preview` 若印「Port 4173 is in use, trying another one...」,
    **不要假設它在 4173** —— 本機可能有別場 session 的舊 preview 還開著,
    打錯 port 會驗到一個舊 build 而且全綠(0916 差點踩到)。用 `BASE=` 指定它印的那個。

■⑦ 部署

  npm run build
  npx wrangler pages deploy <dist 的絕對路徑> --project-name dragtetris --branch main

  ⚠ 部署前的 zero-pii-guard 會擋「目錄用 shell 變數傳」:`--assets $dist` 會被拒絕,
    要寫**展開後的絕對路徑**(守門讀的是原始指令字串,shell 還沒展開)。
  ⚠ 部署目錄給絕對路徑,並先 `Push-Location` 到一個純 ASCII 的**空**目錄再跑
    (cwd 就是 assets 夾時,wrangler 會把含 Cloudflare 帳號 id 的
     `.wrangler/cache/wrangler-account.json` 寫進去並當成靜態資產公開)。

  線上  https://dragtetris.pages.dev   ← 大廳卡片指這裡
        (另有 netlify 鏡像;sites.json 登記的是 pages.dev)
